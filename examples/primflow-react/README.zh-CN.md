# Prim flow React 示例

[English](README.md) | 简体中文

从仓库根目录运行：

```sh
pnpm dev
```

默认直接加载各个 workflow 库的源码。使用 `pnpm dev:dist` 可让示例加载库的构建产物。

本应用是库能力的集成演示，不是独立的云端工作流服务。库能力与限制见根 [README](../../README.zh-CN.md)，节点、文件与事件链路见 [内部 workflow 文档](packages/workflow/README.zh-CN.md)。

示例按浏览器语言选择简体中文或英文：`packages/workflow/i18n.ts` 读取 `navigator.language` / `navigator.languages`，用首个受支持的语言决定页面文案、节点目录、节点定义、工具栏和画布内置 UI（通过 `GraphOptions.language`）。不支持的语言回退英文；页面不提供语言切换入口，语言只影响展示，不改协议值或已保存的图数据。

## GitHub Pages

[在线示例](https://lyx-pj.github.io/primflow-js/) 使用 `/primflow-js/` 作为基础路径。要在本地预览同样的构建，从仓库根目录运行：

```sh
pnpm build
pnpm --filter primflow-react-example build --base=/primflow-js/
pnpm --filter primflow-react-example preview --base=/primflow-js/
```

打开预览服务的 `/primflow-js/` 路径。工作流仍通过 IndexedDB 保存在各位访问者自己的浏览器中，Pages 不提供共享的服务器存储。

## 代码结构

`src/App.tsx` 直接组合 `GraphProvider`、`EngineProvider` 和 `GraphView`，保留最少的画布布局。
`src/components/ViewSwitcher.tsx` 是左上角的文件下拉框，按普通视图和子图分组，基于 `@headlessui/react` 的 Listbox 加 Tailwind 实现。
`src/components/ViewNameDialog.tsx` 是填写文件名称的居中弹窗，新建和重命名共用；遮罩、焦点陷阱和 Esc 关闭交给 Headless UI 的 Dialog，表单控件用 Field / Label / Input / Button。
`useWorkflow` 连接工作流事件、文件切换和自动保存。

与工作流有关的示例代码集中在 `packages/workflow`，方便从同一目录查找节点及其关联配置：

```text
packages/workflow/
├── index.ts                  # 示例使用的统一入口
├── context/
│   ├── graph-context.ts      # 画布上下文、节点默认值和面板配置
│   ├── asset-editors.ts      # 文件类型的端口编辑器和面板编辑器
│   ├── asset-preview.ts      # 资产对象 URL 缓存，供节点卡片和面板预览
│   ├── node-renderers.ts     # 演示节点和图片文件节点的自定义卡片
│   └── engine-context.ts     # 执行引擎上下文
├── i18n.ts                   # 浏览器语言检测、应用文案与语言覆盖
├── nodes/                    # 节点定义、执行器、注册及分类目录 catalog.ts
├── events.ts                 # 工具栏操作、断点、执行状态与调试面板数据同步
├── debug.ts                  # 引擎执行日志到面板日志的转换与业务日志通道
├── records.ts                # 执行记录来源与标题，在任务创建时固定
├── scopes.ts                 # 从任务图解析节点标题与子图作用域
├── storage.ts                # 视图 / 子图文件的 IndexedDB 存取与类型识别
├── views.ts                  # 文件 id、默认命名、存档校验和子图 Start id 规范化
├── subgraphs.ts              # 子图面板条目与执行前的跨文件组装
└── use-workflow.ts           # 将事件、文件切换和自动保存接入 React 生命周期
```

这里的 `packages/workflow` 是示例内部模块，通过相对路径导入。通用的模型、引擎、画布和 React 适配器仍来自仓库根目录的 `packages/*`。

## 视图与子图文件

子图数据、参数规则和画布导航分别见 [model 子图数据与端口](../../packages/primflow-model/docs/subgraphs.zh-CN.md)、[engine 子图参数](../../packages/primflow-engine/docs/subgraphs.zh-CN.md)、[canvas 子图与导航](../../packages/primflow-canvas/docs/subgraphs.zh-CN.md)。

从画布双击独立子图节点进入编辑后，在画布空白处连续右键两次可返回来源文件，也可用「返回上一层」按钮、右键菜单或 `Esc`。连续进入多个子图时逐层返回；若从循环体内进入，返回后恢复当时的内嵌层级。导航路径只保留在当前会话，通过文件列表直接选择、新建文件或删除当前文件时清空，删除来源文件时移除对应路径。返回前先保存当前文件；保存失败留在原文件并保留路径，加载失败仍可返回来源且不覆盖失败存档。

工作流按「文件」分别保存：左上角下拉框把普通视图和子图分开列出，当前文件用行首对勾标记。子图是独立存档，可以单独新建、重命名、删除和切换编辑；画布上的子图节点只引用子图文件的 id，双击节点或在下拉框里选择就会切换到该文件。文件菜单中的「新建…」打开居中弹窗填写名称，并选择「普通视图」或「子图」；新建子图默认带 Start 和 End，创建后自动切换过去。每个文件独立保存节点、连线、变量和视口，子图不随调用方视图一起保存。视口窄于 768px 时，文件选择器变为画布上方的顶栏，画布切换为紧凑布局：侧边面板作为全宽面板停在工具栏下方。文件列表保存在 IndexedDB 的 `bpgraph/views` 仓库里，元数据区分普通视图与子图；重新打开页面会恢复上次使用的文件，读取完成前显示加载遮罩，避免先闪出默认画布。内嵌区域随所属视图保存和双击进入，独立子图文件单独保存并由调用节点引用。

工作流会自动保存：画布内容或视口（缩放、平移）变化后 600 毫秒落盘到当前文件，右下角显示「待保存 / 保存中 / 已保存 / 保存失败」；`Ctrl/Cmd + S` 仍可立即保存当前文件。切换文件前会先把当前文件的改动落盘，避免写进目标文件。工具栏支持执行、调试、继续和停止；启动执行时会先按节点上的引用从存储读取独立子图文件，组装后交给引擎，子图文件里嵌套的子图也会递归加载。右侧调试面板用工具栏中的终端图标显示或隐藏，展示执行记录和执行日志；节点面板默认打开，由工具栏的侧栏图标控制，选中节点不会自动弹出；总览标签页会列出当前视图的节点，点击即可定位；日志直接来自引擎的执行日志，每条带引擎事件类型（如 `activation:status`、`task:status`），业务输出（「调试输出」节点的内容）作为应用日志并入同一条流。执行记录按任务列出，当前正在执行的任务也会显示，状态为「运行中」，结束后状态更新为「已完成」或「失败」等最终状态。记录标题按发起它的来源命名：普通视图是「执行【视图名】」，子图文件是「执行【子图】【子图名】」，事件触发的执行是「执行事件【监听节点】【事件名】」；名称在任务创建时定格，之后切换文件也不会改写历史记录。点击一条已结束的执行记录会切换到该次任务的日志，并把画布切到对应任务图的历史快照；运行或回溯时，悬停节点可在画布卡片里查看执行状态，已完成的节点还会显示输入和输出。调试面板继续显示当前记录。再次点击当前记录、点击左下角「退出回溯」或按 Esc 会恢复编辑图；回溯期间自动保存暂停，避免把历史快照写进当前文件。循环体仍内嵌在所属文件里，进入后可通过工具栏的「返回上一层」、空白处右键双击、空白处右键菜单的「返回上一层」或 `Esc` 返回；为识别右键双击，循环体内的空白右键菜单会延迟约 300ms 打开。macOS 若开启「智能缩放」（Smart Zoom），双指轻点两次会被系统当作缩放手势，不会产生两次右键事件；此时请用双指按压（click）两次、关闭智能缩放，或直接使用返回按钮 / `Esc`。

执行和调试通过 `engine.start({ debug })` 启动，不传入默认业务数据。
点击「停止」后，最新任务中已取消的节点会保持橙色光晕，直到下一次运行。回溯会显示选中任务记录的节点状态。
普通视图的 Start 仅通过一个执行出口触发后续节点，节点面板不展示 Inputs/Outputs；业务数据在业务节点中配置。独立子图文件的 Start 可保留显式参数端口，用于调用方传参。

## Demo 节点

双击画布空白处或通过右键菜单打开添加面板。面板支持分类筛选、名称与用途搜索、点击添加和拖拽添加，业务节点提供演示默认值。

| 分类 | 节点 | 演示内容 |
| --- | --- | --- |
| 基础输入 | 文本输入、数字输入、开关输入、数组输入、对象输入、多行文本输入、下拉选择 | 只带数据端口，按需提供值 |
| 变量 | 设置变量、获取变量 | 读写当前任务中按名称保存的 JSON 值 |
| 文本处理 | 拼接文本、文本模板、拆分文本、校验字符串 | 字符串处理、`{{value}}` 替换、数组与数量输出 |
| 数据计算 | 四则运算、数值比较 | 下拉选项、算术计算、布尔结果 |
| 流程控制 | 开始、条件分支、多路分支、等待、人工审批、抛出错误、循环、定时器 | 分支、取消、业务中断、失败、循环与定时触发 |
| 事件 | 事件触发、事件监听 | 发出 / 监听业务事件、独立任务执行、生命周期订阅与清理 |
| 网络 | HTTP 请求 | 通过引擎服务发送浏览器请求，输出响应并按状态码分支 |
| 输出调试 | 调试输出 | 任意类型输入、执行数据预览与控制台日志 |

把 Start 的执行线接到需要运行的节点，再把基础输入的数据输出接到该节点。基础输入只有数据端口，引擎为下游节点准备输入时，才读取基础输入的配置值或连线值。下拉选择输出所选项对应的字符串值。

选中输入节点可打开设置面板。数组和对象使用 JSON 编辑，离开编辑框时应用有效修改，格式或类型有误时保留原值。

示例默认值无需 API Key 或外部服务。把 Start 接到「HTTP 请求」再运行，即可读取示例自带的 JSON。要请求其他接口，可填写 URL 并选择 GET、HEAD、POST、PUT、PATCH 或 DELETE。除 GET 和 HEAD 外，可提供 JSON 对象作为请求体。节点输出状态码以及解析后的 JSON 或文本。2xx 走「成功」，其余 HTTP 响应走「HTTP 错误」。请求本身失败（网络不可达、CORS 拦截、地址协议非法）同样走「HTTP 错误」，状态码输出 `0`，失败原因输出到响应体。URL 为空或方法不支持属于配置错误，节点直接失败。停止工作流会取消进行中的请求。跨域接口须通过 CORS 允许示例所在的来源。
条件分支使用布尔条件，数值比较的结果可以直接连接；等待节点支持 0–60000 毫秒，停止运行会取消等待。
子图不在静态节点表里：当已有子图文件时，添加面板会多出「子图」分类，每个子图文件对应一条调用节点，新建后自动绑定该文件的 id 和名称。

### 体验执行状态

- 连接「开始 → 人工审批」，把「通过」出口接到「调试输出」，把「拒绝」出口接到「抛出错误」。执行后可以看到紫色光晕和「待审批」面板。点击「通过」或「拒绝」后，相应分支开始执行，未选分支亮起灰蓝色光晕。「抛出错误」执行时亮起红色光晕，配置的消息会显示在调试日志里。「审批结果」数据出口在通过时输出 `true`，拒绝时输出 `false`。
- 连接「开始 → 等待」，把等待时间调长。运行后在节点仍执行时点击「停止」，可看到橙色取消光晕。停止也会取消待审批的执行，并关闭待审批面板。

事件节点演示引擎的任务与节点生命周期钩子，定时器演示长期运行并反复触发下游的执行器：

- 事件触发使用执行上下文的 `ctx.emitEvent(event, payload)` 发出事件，事件会创建独立任务，触发节点不等待监听节点。
- 事件监听没有执行入口，在 `onActive` 中用 `ctx.on` 订阅配置的事件名；每次事件在独立任务的上下文中写入「事件数据 / 收到次数」并 `next()`，`onDeactivate` 退订、`onDestroy` 清理状态。
- 定时器归入流程控制，不订阅也不依赖事件：执行器按「间隔（秒/分/时）」或「每天 HH:mm」等待下一次触发，触发时写入「触发时间 / 触发次数」并调用 `next()` 直接执行连接的下游，停止运行会通过任务 `signal` 取消等待。触发方式、间隔单位与每天时间在节点面板配置。

### 用变量体验修正后重试

按下面的步骤搭出这个场景，点击「运行」后打开调试日志，查看 `wrong` 校验失败、修正分支写入 `ready`，以及重试时重新读取变量并通过校验的过程。

「设置变量」在执行时写入当前任务的 JSON 状态。「获取变量」用数据线连接，下游准备输入时才读取。同一任务的分支可以共享变量。变量名填在节点上；直接输入字符串时使用节点的「值」，其他 JSON 值可以由数据端口传入。

1. 连接 `开始 → 设置变量`，将 `status` 设为 `wrong`。
2. 从第一个「设置变量」的执行出口分两路。一条执行线直接接「校验字符串」。另放一个「获取变量」，将它的「值」用数据线接到校验节点的「实际值」，期望字符串填 `ready`。另一条走 `等待 → 设置变量`，把等待设为 `200` 毫秒，再将同一个 `status` 设为 `ready`。
3. 运行并查看调试日志。首次校验收到 `wrong`。修正分支提交后，引擎重试校验时会按需重读变量，读到 `ready` 后通过。

也可以让两个分支直接从「开始」出发，省去初始写入。如果「校验字符串」先于延迟分支读取，第一次尝试会记录 `VARIABLE_NOT_FOUND`。「校验字符串」最多重试两次，读到 `ready` 即可继续。悬停校验节点，或打开节点面板底部的「执行信息」，可查看尝试次数和错误详情。

### 循环节点

循环节点、执行规则和画布编辑分别见 [model 循环节点](../../packages/primflow-model/docs/loops.zh-CN.md)、[engine 循环执行](../../packages/primflow-engine/docs/loops.zh-CN.md)、[canvas 循环体](../../packages/primflow-canvas/docs/loops.zh-CN.md)。

循环节点是子图式容器：节点本身提供执行端口与数据端口，循环体保存在所属文件的 `subgraphs` 中。添加循环节点时画布自动创建循环体，里面有一个「循环入口」和一个「循环返回」；双击循环节点即可进入循环体编辑内部节点；节点面板由工具栏按钮控制，打开后切换节点会立即更新。循环体不单独成文件，随所属文件一起保存。返回上一层使用工具栏的「返回上一层」按钮、空白处右键双击、空白处右键菜单的「返回上一层」或 `Esc`。

| 端口 | 方向 | 说明 |
| --- | --- | --- |
| `exec` | 输入 | 进入循环，按配置开始执行 |
| `input` | 输入 | 循环输入：首轮循环体的入口值 |
| `done` | 输出 | 所有轮次成功结束后触发一次 |
| `output` | 输出 | 循环输出：最后一轮循环体提交的值 |

循环对外只有一个入口和一个出口：轮次、结束原因由引擎内部维护，可通过循环查询 API 查看；目前没有专门的轮次面板。

循环体自动生成的端口：

| 节点 | 端口 | 说明 |
| --- | --- | --- |
| 循环入口 | 输出 `exec`、`value`、`initialValue` | 分别提供本轮迭代输入和初始输入 |
| 循环返回 | 执行输入 `next` / `break`；数据输入 `value` | 提交下一轮输入或最终输出 |

规则：

- 循环体必须有且只有一个循环入口、至少一个循环返回，不能放普通「开始」节点；入口与返回由画布创建循环体时生成，不会出现在添加面板里，也不能单独删除。新建循环体自带「循环入口.exec → 循环返回.next」连线，添加业务节点后替换这条连线即可。
- 循环只有一种形态：循环体反复执行，什么时候结束由循环体自己决定（走到循环返回的 `break`）。遍历集合、计数等玩法由循环体里的节点实现。
- 每轮使用独立的节点输入输出和执行状态，上一轮的临时值不会留给下一轮；跨轮的值通过「循环返回.value」提交给下一轮的「循环入口.value」。
- 各轮串行。某轮没有到达循环返回、重复返回或数据依赖无法满足时任务失败，不会继续下一轮。
- 循环体一直没有走到 `break` 时，按轮数上限失败（`LoopLimitExceeded`），不会发布部分结果，也不会触发「完成」。
- 单击 Loop 节点可设置「最大循环次数」和「超时（毫秒）」。两项都留空时，次数沿用引擎上限（默认 1000 轮），循环不设超时。
- 循环体内可以继续添加普通节点、子图调用节点或嵌套循环；事件监听、定时器等事件源会被执行前校验拒绝，添加面板在循环体内会直接隐藏它们。

演示流程（执行端口与对应数据端口都要连线）：

- 开始 → 四则运算 → 循环：把四则运算的「结果」接到循环的「初始值」（`input`），把循环的「完成」接到循环后的调试输出。进入循环体后接成「循环入口 exec → 四则运算 exec」，「循环入口 value → 四则运算 数值A」，「四则运算 完成 → 数值比较 exec」，「数值比较 结果 → 条件分支 条件」，「条件分支 满足 → 循环返回 break」，「条件分支 不满足 → 循环返回 next」，「四则运算 结果 → 循环返回 value」。这样每轮把数值加一，超过阈值时结束循环，循环的「循环输出」是最后一轮的数值。

可以尝试这五条流程（执行端口与对应数据端口都需要连线）：

- 开始 → 拆分文本 → 文本模板 → 调试输出：将拆分的「数量」接到模板的「替换值」，再将模板文本接到输出的「内容」。
- 开始 → 数字输入 → 四则运算 → 数值比较 → 条件分支 → 调试输出：将各节点的数据结果依次相连，通过「满足 / 不满足」执行出口选择分支。
- 开始 → 事件触发 → 调试输出，同时把「事件监听」接到另一个调试输出：执行后监听节点会在独立任务中输出事件的「事件数据」，事件被多次发出时「收到次数」递增。
- 开始 → 定时器 → 调试输出：把定时器的「触发时间」接到调试输出的「内容」，执行后会按配置的间隔（或每天指定时间）反复输出，「触发次数」递增；停止运行后不再触发。
- 开始 → 四则运算 → 循环 → 调试输出：按上面的演示流程接好循环体，循环体每轮自己判断是否结束，结束后才触发「完成」。

分类、说明、关键词和默认值集中在 `nodes/catalog.ts`。画布通过 `palette.describe` 读取展示信息，保持通用模型与 demo 业务分离。
节点图标统一使用 Remix Icon 字体图标，由示例入口加载 `remixicon/fonts/remixicon.css`，字体文件随 Vite 构建打包，不依赖外部 CDN。
存档包含未注册的节点类型时，会提示该视图无法恢复并保留原存档；此时该视图的自动保存暂停，可以切到别的视图继续编辑，或按 `Ctrl/Cmd + S` 用当前画布覆盖它。

### 文件

用「图片文件」上传图片。文件内容保存在当前浏览器的 IndexedDB，图只保存引用；重新打开工作流后图片仍然可用。

文件控件是应用为图片数据类型注册的编辑器。「图片文件」节点不提供可连线的图片输入，卡片中间的文字按钮直接打开系统文件选择器，选中的图片显示在按钮下方，输出端口位于卡片右侧边缘。节点面板里仍提供完整的选择器、已存资产和图片预览。参见 [画布自定义编辑器](../../packages/primflow-canvas/README.zh-CN.md#自定义编辑器) 与 [画布自定义节点渲染](../../packages/primflow-canvas/README.zh-CN.md#自定义节点渲染)。

添加「自定义节点」可以看到由应用绘制的节点主体。它保留标准执行端口，但自己绘制卡片，不使用内置的标题栏和主体；端口贴在卡片边框上，卡片上的文字跟随节点的 `label` 值。它还会重排面板区块：提示放在最前，Inputs 移到元信息上方，并隐藏输出区块。参见 [画布自定义节点渲染](../../packages/primflow-canvas/README.zh-CN.md#自定义节点渲染)。
